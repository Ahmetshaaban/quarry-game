QUARRY

Agent API. Everything the browser client does is available over plain HTTP with JSON bodies; no key, no login, no SDK. Base URL is the same origin that serves the game.

Rules in one paragraph

Four quarries (Ruby, Amber, Jade, Azure) start with nine stones each. On your turn you take one or two stones from a single quarry, or spend your once-per-match Double Shift to take one stone from each of two different quarries. Play continues until every quarry is empty. Each quarry pays only a strict leader: that player scores their stones in the quarry minus the runner-up's, and a tie for the lead pays nobody. Taking the last stone of a quarry earns that player a Seal, worth two points. Highest total wins, and a tie on points is broken by total stones collected.

Endpoints

Method and pathPurpose
GET /api/healthLiveness plus a copy of the rules.
POST /api/roomsCreate a room. Body: {"name":"...","bots":2,"difficulty":"medium","autostart":true}. Returns code, seat, token.
POST /api/rooms/{code}/joinTake the next empty seat. Body: {"name":"..."}. Returns your seat and token.
POST /api/rooms/{code}/botSeat a server bot in the next empty seat while the room is in the lobby. Body: {"difficulty":"hard"}.
POST /api/rooms/{code}/startStart the match (host only). Body: {"token":"..."}. Needs at least two occupied seats.
GET /api/rooms/{code}/state?token=...Full public state. With your token the same object also carries you with you.legalMoves, you.isYourTurn and you.holdings.
POST /api/rooms/{code}/movePlay a move. Body: {"token":"...","id":"take:ruby:2"}, or the explicit form {"token":"...","action":"take","quarry":"ruby","count":2}.
GET /api/rooms/{code}/logThe complete match record: seats, every move, holdings, and the final result.

Every response is JSON. Successful calls carry "ok": true; failures carry "ok": false with an error code (NOT_YOUR_TURN, ILLEGAL_MOVE, BAD_TOKEN, ROOM_FULL, NOT_ENOUGH_SEATS, MATCH_FINISHED, ...) and a human-readable message. CORS is open, so an agent can play from anywhere.

Move identifiers

Read you.legalMoves and post one of the returned id values verbatim - that is the whole decision surface, about eighteen options a turn:

{
  "id": "take:ruby:2",
  "action": "take",
  "quarry": "ruby",
  "count": 2,
  "description": "Take 2 stones from the Ruby quarry."
}

{
  "id": "shift:amber+jade",
  "action": "shift",
  "from": [{"quarry": "amber", "count": 1}, {"quarry": "jade", "count": 1}],
  "description": "Double Shift: ..."
}

A full agent match in five calls

BASE=https://your-quarry-host

# 1. open a room and keep the token
curl -sX POST $BASE/api/rooms -H "Content-Type: application/json" \
  -d '{"name":"Agent One"}'

# 2. seat three bots so the room is playable on its own
curl -sX POST $BASE/api/rooms/CODE/bot -H "Content-Type: application/json" -d '{"difficulty":"medium"}'
curl -sX POST $BASE/api/rooms/CODE/bot -H "Content-Type: application/json" -d '{"difficulty":"medium"}'
curl -sX POST $BASE/api/rooms/CODE/bot -H "Content-Type: application/json" -d '{"difficulty":"medium"}'

# 3. start the match (host seat only)
curl -sX POST $BASE/api/rooms/CODE/start -H "Content-Type: application/json" -d '{"token":"TOKEN"}'

# 4. poll until it is your turn, then read the legal moves
curl -s "$BASE/api/rooms/CODE/state?token=TOKEN"

# 5. play one legal move
curl -sX POST $BASE/api/rooms/CODE/move -H "Content-Type: application/json" \
  -d '{"token":"TOKEN","id":"take:ruby:2"}'

# the finished match, move by move
curl -s $BASE/api/rooms/CODE/log

A ready-made player lives in the repository at sample-bot/agent_bot.py (standard library only). Point it at a room with --code, or let it open and finish its own match against bots.

Notes for agent authors

  • Send a User-Agent header that names your agent. Some CDNs and proxies refuse anonymous default user agents, and an identified client never trips those rules.
  • The state is fully public: no hidden information, so a planner can search the game tree directly. Branching is about fourteen moves a turn and a match lasts roughly twenty turns.
  • Seats that run out of time are played automatically, so a match always terminates even if a client stops polling.
  • A room is kept for twenty-four hours after the last move; finished matches are written to disk and remain readable through /api/rooms/{code}/log.
  • Reconnecting is just the same token again; it survives page reloads, server bots and agent restarts inside that window.
